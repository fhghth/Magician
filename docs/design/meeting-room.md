---

## 0. 一句话定义

会议室是 Agent 系统的**审议层**：在现有"分派—执行"能力之上，增加对等辩论、交叉质证与共识固化能力，用结构化讨论换两个可度量的结果——**复杂任务一次做对的概率提升**，**关键信息的抗衰减记忆**。

本功能不做"多专家聊天秀"。一切设计取舍以**效率**与**降幻觉**两个指标为准绳，代码处理与复杂任务是主战场。

---

## 1. 背景：现有能力的四个结构性缺陷

当前多 Agent 能力 = 父子任务树（hub-and-spoke 分派）+ kanban 编排（auto-decompose、按 profile 路由）。这是单向结构，存在：

1. **幻觉复利**：分派链中没有"质疑"通道。父 Agent 的错误前提被子 Agent 忠实执行并逐级放大，无人反驳。
2. **记忆衰减**：长任务上下文压缩后，关键约束（数字、边界条件、否决项）被摘要吞掉，且 Agent 不知道自己忘了——不会触发任何检索。
3. **无事中介入点**：用户只能在任务结束后看到结果，执行中无法纠正方向。
4. **编排器没有升级路径**：遇到"不该直接干、需要先想清楚"的任务（方案分歧大、风险高、置信度低），现有系统只能硬派给某个 Agent。

会议室即为补齐这四点而生。

---

## 2. 目标与衡量指标

| 目标 | 指标 | 度量方法 | 目标值 |
|---|---|---|---|
| 效率 | 复杂任务一次通过率 | 同一任务集 A/B：单 Agent vs 会议模式，统计无需返工/人工纠错的完成比例 | ≥ +30% 相对提升 |
| 降幻觉 | 事实性错误率 | 产出物中定量断言的溯源失败比例（抽样审计，见 §4.3 溯源机制） | ≤ 基线的 1/3 |
| 自主性 | 离场完成率 / 事后否决率 | 会议存续期间（用户离场、程序存活）无需用户返工的比例；用户回放后发起否决的比例 | 完成率 ≥ 80%，否决率 ≤ 10% |
| 干预成本 | 平均每任务用户介入次数 | 埋点统计 | 随版本递减 |
| 经济性 | 单任务 token 成本 / 通过率比 | 现有 subagent 成本追踪字段扩展 | 比值不劣于单 Agent 重试 |
| 系统健康 | 死锁次数 / 熔断触发率 | 调度引擎日志 | **死锁必须为 0**（由必然终止性保证） |

## 3. 核心概念表

| 概念 | 定义 |
|---|---|
| 会议室 MeetingRoom | 一次有议题、有预算、有强制产物的审议会话 |
| 轻量会诊 | 1v1 简化会议档（提出者 + 红队、规则调度），中等复杂度任务的低成本入口（§4.1） |
| 发言权令牌 Floor Token | 全会议唯一，一切发言经调度器串行化，LLM 只有提议权 |
| 关键帧 Keyframe | 被钉住的**逐字**原文片段，永久驻留参会者上下文 |
| 决策账本 Decision Ledger | 结构化、带原文指针、版本化只追加的事实层 |
| 权威阶梯 | L0 用户 > L1 主持人 > L2 记录员 > L3 参与者 |
| 实施契约 Implementation Contract | 会议产出给编码 Agent 的结构化 spec（非聊天记录） |
| 委托授权 Delegation Profile | 用户离场、会议存续期间 AI 可自主拍板的决策边界（白/灰/黑名单） |

## 4. 系统架构（五层）

### 4.1 触发层：四种入口

1. **用户手动发起**：独立会议室入口 / 对话中一键转入（抓取当前上下文为背景材料）。
2. **kanban 卡片转入会诊**：卡片打"需会诊"标签，自动从卡片描述生成议题。
3. **编排器自动升级**：decompose 阶段判定复杂度/风险超阈值 → 生成**会议申请**而非直接派单。
4. **执行中 Agent 主动申请**：置信度低、多方案分歧、不可逆操作前，挂起当前任务并申请会诊。

**会议申请五要素**（所有非用户入口必须提交）：
议题 / 参会者名单与角色 / 三重预算（回合数、时长、token 各设硬顶）/ 预期产物类型 / 申请的决策权限级别。

有人值守 → 用户弹窗确认；用户离场（程序存续期间）→ Delegation Profile 自动裁决（§4.4）。

**席位配置默认（宁少勿多）**：会议价值 = 视角差异 × 质证强度，与人数无关；令牌串行化使每席的延迟与 token 线性上涨，边际收益随观点相关性递减。分两档默认：

- **轻量会诊（1v1）**：提出者 + 红队，调度退化为纯规则轮流发言；kanban 中等复杂度卡片转入用此档，§4.2 全套熔断仍适用。
- **完整会议（默认 3 席）**：提出者 + 红队 + 领域专家（读代码 / 日志 / 文档的证据位），高风险 / 低置信度任务启用。主持人由主 Agent 兼任、记录员为机制而非席位，均不占人头。

**动态增员优于开局坐满**：主持人可中途邀请新专家入会（占用预算），而非开局按最坏情况配满。席位与三重预算联动：N 席每回合成本 ×N，会议申请的预算按席位自动缩放并向用户透出（"5 人局约消耗 X token/回合"）。

### 4.2 调度层：确定性引擎（LLM 提议，代码裁决）

会议的可存活性不允许依赖任何单次 LLM 调用。

- **封闭动作集**：主持人 Agent 的输出被 structured output 限制为 `{next_speaker | park_topic | summarize | escalate_to_user | close}`。输出非法或 10s 超时 → 自动降级到兜底调度器（优先级：被@者 > 被追问者 > 领域相关度 > 举手先后）。
- **优先级事件队列**：`P0 用户打断 > P1 熔断事件 > P2 用户答复待办 > P3 Agent 回合 > P4 后台摘要`。
- **@环检测**：同一对 Agent 在单议题内互 @ 超过 2 次 → 不再产生新回合，自动转为"争议点"搁置并升级。
- **三级熔断**：
  1. 单回合 60s 无产出 → 令牌移交下一位，半成品标注"发言中断"；
  2. 语义循环：连续 4 回合相似度超阈值 → 强制主持人"收敛或升级"；同一议题触发 3 次 → 议题自动搁置 + 通知用户；
  3. 熔断触发后涉事 Agent 对进入 M 回合冷却，禁止互 @。
- **必然终止性（liveness 保证）**：三重预算任一耗尽 → 强制收敛流程：记录员立即出账本级纪要，全部未决事项进入待签章队列。程序退出 → 会议收尾落库（与单对话同构，见 §6 S3）。**数学上不存在跑飞的可能。**
- **用户插嘴 = P0 中断**：真实 abort 进行中的流式请求（非前端隐藏），已产出部分折叠保留并标注"被打断"，令牌立即移交。区分"暂停会议"（冻结调度器）与"强制插话"（抢令牌）。

### 4.3 记忆层：三层存储 + 回灌（"加强记忆"的工程实现）

- **Tier 0 原文层**：append-only 全量落盘，永不删除。存储便宜，上下文才贵。它是审计证据链与回放数据源。
- **Tier 1 关键帧层**：小容量、逐字、永久驻留所有参会 Agent 上下文。四个来源：
  1. 用户长按"标记为关键"（一等公民操作）；
  2. 记录员**按固定 schema 抽取**（决策 / 金额与数字 / 日期 / 承诺 / 例外条款 / 待办），每条带原文 messageID 指针——存结构化账本，不存散文；
  3. Agent 工具调用 `pin_message(id, reason)` 自标记；
  4. 规则触发：数字、金额、"以 X 为准"等模式正则 → 候选帧，记录员确认。
- **关键帧 clearance 维度**：关键帧"驻留所有参会者上下文"等于向所有厂商广播，而规则触发的候选帧（数字 / 金额 /"以 X 为准"）恰是最敏感内容。每帧携带 clearance 级别，注入某参会者上下文前按其 endpoint 信任分级过滤或脱敏（出域闸门见 §11.1 第 2 条）。
- **Tier 2 滚动摘要 + 最近 N 轮原文**（同原方案）。
- **版本化账本**：决策修订只追加不改写（旧值→新值→提议人→时间戳）。Agent 需要数字时读账本，不读摘要转述。
- **防漂移对账**：每 K 轮用账本反向核对摘要中的数字，不一致自动修正并标记。
- **断言三级分类（降幻觉核心）**：记录员将发言抽取为 `事实（带引用：文件/行号/文档/账本条目） | 推断 | 观点`。只有"事实+引用"可进入账本；**无引用的定量断言禁止进入纪要与实施契约**。
- **回灌机制**：会后账本条目 + 关键帧注入后续执行 Agent 的初始上下文；**项目级账本**跨会议持久化，新会议/新任务自动装载相关历史条目（含历史教训、历史否决项）。这就是"通过讨论让在场 AI 明确加强记忆关键信息"的落地路径：讨论 → 质证 → 钉住 → 结构化 → 回灌。

### 4.4 权限层：权威阶梯与委托授权

**权威阶梯写进数据模型**：L0 用户 > L1 主持人 > L2 记录员 > L3 参与者。L0 独占最终决策权。

**结论状态机**：`提议 → 待确认 → 已决策（签章）`。无签章的结论只是建议，不得作为执行依据。

**有人值守：人类独裁模式**——常驻控制条五个 P0 级按钮：
- **否决**：将任意发言/摘要/结论标记"已被用户否决"，作为硬约束注入所有 Agent 上下文（标记而非删除，Agent 需要知道边界）；账本同步注记。
- **接管主持**：一键剥夺 Agent 主持人令牌，降级为参与者。
- **一言堂**：直接发布"以方案 B 为准"→ 绑定决策事件注入全场、写入账本、议题自动关闭（可配置为允许继续讨论但决策生效）。
- **暂停 / 终止**。

**离场模式：委托授权协议（Delegation Profile）**——会议存续期间（程序存活）用户离场时，其否决权转化为**事前圈界 + 事后回溯**；程序退出即会议收尾，待签章事项转入"待回放"队列等用户返回：

| 名单 | 内容 | 处理方式 |
|---|---|---|
| 白名单 | 实现方案选择、测试策略、重构范围、依赖补丁级升级、内部文档生成 | AI 可自主签章并执行 |
| 灰名单 | 可执行但标记"待追认"：新文件创建、较大重构、非平凡依赖变更 | 执行后进入待追认队列，用户一键追认/否决 |
| 黑名单 | 不可逆操作（删除、发布、付费、对外可见变更）、schema 迁移、超预算 | **不可配置删除**；触发即挂起，进待签章队列等用户 |

- **回溯否决与补偿**：用户回来后基于 Tier 0 原文 + 事件流倍速回放（支持只看账本 diff），可对任一已执行决策点否决 → 触发补偿动作（git revert / 文件恢复 / 任务回滚），账本记录否决链。
- **主持日志**：全部调度、签章、熔断、否决动作留痕，供复盘审计。

### 4.5 产物层：禁止"纯讨论"

每次会议必须产出以下至少一项，否则记为异常会议：

1. **实施契约**：目标 / 约束 / 验收标准 / 测试要求 / 禁止事项 / 溯源引用。编码 Agent 拿契约干活——幻觉在执行端被验收标准拦截。
2. **决策纪要**（账本级，每条结论可展开到原文行）。
3. **待签章队列**（黑名单/灰名单事项）。
4. **教训条目**（复盘会产出 → 项目级记忆）。

## 5. 降幻觉机理：为什么是会议而不是更强的单 Agent

1. **异构质证**：参会者尽量跨底座模型（不同厂商 / 本地模型混搭），系统性错误相关性低；强制存在"红队"角色，其唯一 KPI 是反驳。红队资格由金丝雀评测把关：固定"埋雷"样本集（错误数字 / 错误 API 用法 / 隐性逻辑漏洞），抓出率不达标即取消红队资格、仅作参与者，模型更新后重跑（§11.1 第 3 条）。
2. **断言分级 + 强制溯源**：把"说得自信"和"拿得出引用"解耦（§4.3）。
3. **关键帧钉住**：2 小时前的关键约束不会被摘要吞掉。
4. **账本对账**：摘要漂移被周期性抓出并修正。
5. **实施契约拦截**：执行端按验收标准校验，错误共识无法直接变成代码。

**反风险——集体同温层**：多个 Agent 互相强化错误共识，幻觉反而被放大。对策：红队配额制（每议题至少 N 条实质反驳才允许收敛）、尽量异构模型 + 红队金丝雀门槛、签章权始终在 L0 或白名单边界内。

**红队拆解与降级链**：红队是一捆检查而非单一角色——开放式质证（需强模型）、引用核验 / 数字对账 / schema 校验（机械检查，弱模型或纯代码即可，直接服务 §4.3 强制溯源）。无本地模型时按链降级：① 跨厂商 API 异构（红队席位默认选与提出者不同厂商的已配置模型）→ ② 同模型异质化（红队只见"断言 + 证据"，不见推理链与讨论史，以信息不对称防锚定；换 persona、调温度仅为辅助手段）→ ③ 纯机械检查模式（诚实降级，不做假质证——虚假制衡比没有制衡更糟）。质证变弱必须由另两道防线补偿：白名单收窄、签章门槛上移（关键结论需 ≥2 条带引用"事实"支撑）、溯源要求变硬（无引用断言连纪要都不得进）。最差组合是红队形同虚设而权限照常放行——幻觉复利原样保留，只是多花了开会 token。

## 6. 典型场景

- **S1 架构评审会**：改核心模块前，主 Agent 申请召集 → 方案 A/B 辩论 → 红队质疑 → 产出实施契约 → 编码 Agent 执行。
- **S2 Bug 会诊**：测试反复失败 → 编排器升级为会诊 → 各 Agent 分工读日志/读代码/复现 → 输出根因假设排序（按证据强度）。
- **S3 夜间离场**：长任务白名单内自主推进，黑名单事项挂起；程序需全程保持运行（可熄屏/挂机，退出即会议收尾落库）；晨起用户 10 分钟回放 + 追认/否决。
- **S4 复盘会**：任务失败自动触发，产出教训条目进项目记忆，下次同类任务自动装载。

## 7. UI 布局（桌面端）

会议功能复用桌面端现有"侧边栏 + 主区"骨架，不新发明页面层级。对应用户启动会议的两种场景，分为两套骨架。

---

### 7.1 侧边栏：对话与会议统一列表

现左侧边栏（`apps/desktop/src/app/chat/sidebar/index.tsx`）增加分类分区：

```
┌──────────────┐
│ 🗨 对话        │
│  ├ 对话 A     │
│  ├ 对话 B     │
│ ──────────── │
│ 🏛 会议     + │  ← "会议"分区头部，+ 号弹出新建弹窗
│  🔴 议题甲    │  ← 待回答红点；状态芯片：「●进行中 / ○待回答② / ✓已结束」
│     质疑者发言 │
│     ▓▓▓░ 62% │  ← 预算余量细条
│  ● 议题乙     │
│  ✓ 议题丙     │
└──────────────┘
```

- **分组规则**：同列表内两类分区，会议区排序 = 待回答 > 进行中 > 已结束。
- **P0 限制**：同时仅 1 场会议处于进行中（其余排队/历史查看）；多会议并发留 P2。
- **会议条目额外信息**：小字"来自：某对话"（origin_ref 可视化）。
- **状态徽章**：进行中、待回答（红点+计数）、已收敛、已结束、已中断。
- **选中规则**：选中对话 → 对话模式；选中会议条目 → 会议模式（独立会议）。纯视图状态，由选中项类型驱动，后端无感知。

### 7.2 模式一：独立会议室（三列骨架）

用户从侧边栏选中一个会议，或通过 + 新建后自动进入。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 🏛 议题甲 · ●进行中 · 当前：质疑者 │ 预算余量 ▓▓▓░ 62% │ ⏸ 接管 否决 一言堂 结束│
├──────────┬──────────────────────────────────┬───────────────────────┤
│ 左侧栏    │         主区（圆桌）               │     右侧栏              │
│ (对话/   │                                  │ [对话] [焦点] [回放]    │
│  会议列表)│       ┌─────┐  ┌─────┐           │ ┌───────────────────┐  │
│          │       │协调者│  │提出者│           │ │ 议题A (进行中)      │  │
│          │        ╲   议题   ╱               │ │  ├ 质疑者: …(展开) │  │
│          │     ┌─────┐  ┌─────┐             │ │  ├ 提出者: …      │  │
```

**各区域职责：**

| 区域 | 内容 | 注 |
|---|---|---|
| 头部条 | 议题 + 状态 chip + 当前发言者；预算三顶余量（圆环或细条）；独裁控制条（⏸暂停/接管/否决/一言堂/结束） | 控制条始终可见，不折叠；暂停冻结调度器，接管降级主持人 |

### 7.3 模式二：对话内会议（四列骨架）

用户在对话中执行 `/meeting` 命令或在对话内点击"转入会议"后触发——对话主区压缩，右侧插入会议面板。

**与独立会议模式的关键差异：**

| 项目 | 独立会议 | 对话内会议 |
|---|---|---|
| 对话列 | 无 | 有——压缩宽度（~300–350px），含完整对话消息流 + 独立的对话输入框 |
| 会议列 | 主区圆桌完整形态 | 紧凑——省略圆环/CSS 圆，席位卡片横排 + 当前发言展开 |
| 控制条 | 完整五按钮 | 精简：[暂停] [结束]；否决/接管/一言堂收进 ⋮ 菜单 |
| 输入框 | **1 个**——右侧栏会议输入框 | **2 个**——对话输入框 + 右侧栏会议输入框（**绝对不合一**，见 §7.5） |
| 关闭 | 切回对话列表 | 会议面板收起，对话列恢复全宽 |

**双向交互：**
- 对话输入框的消息发给当前对话模型（行为不变），同时经 P4 后台推入会议作为背景更新（企划 §11.1(6)(b) 正向更新）。
- 会议结束后回流卡片（`meeting_conclusion`）出现在对话消息流中，点击跳回会议回放。

### 7.5 输入框语义红线（验收强制项）

| 规则 | 说明 |
|---|---|
| **一模式一输入框** | 独立会议模式下，**仅**存在右侧栏会议输入框 |
| **一模式两输入框** | 对话内会议模式下，对话输入框与右侧栏会议输入框**物理分离、语义不同、同时可见**——不允许合并、复用、或"上下文路由切换" |
| 会议输入框发送 = 排队插话 | 用户消息写入 `meeting_events(kind=user_interject)`，进入调度器 pending 队列，下一回合开始前作为用户回合注入 transcript |
| 会议输入框长按/Alt+Enter = P0 立即打断 | 复用 `request_hard_interrupt`（`agent/interrupt_compat.py:9`）中止当前席位流式 → 令牌移交用户 |
| 快捷操作行 | 输入框上方：👍 同意某观点 / 🔍 追问细节 / 📌 标记为关键 / ✕ 否决某发言 |

## 11. 开放问题

### 11.1 已决（评审结论，2026-08-05）

1. **召集阈值标定**：先人工规则，复用 kanban 辅助模型现有的复杂度打分（`apps/desktop/src/plugins/kanban/api.ts` 的 L/M/S 估计），在 decompose 同一打分点上增加"可逆性 / 分歧度"维度，不另建评分系统。阈值不是全局常数，而是「值守模式 × 可逆性」的函数：离场模式时漏报代价（无人纠正的幻觉执行）远高于误报代价（token + 延迟），阈值显著拉低；纯本地可逆任务拉高。"学习化"仅做离线特征权重学习（哪些打分维度与"会议改变结论 / 拦截返工"相关），决策规则保持加权分 + 阈值且对用户可解释——被阈值拦下的任务永远没有会议结果，在线学习会在稀疏噪声标签上振荡。免费标注来源：用户确认弹窗的拒绝率。
2. **敏感代码出域**：移出开放问题，列为 P0 前置约束（已并入 §8 P0 范围与验收锚点）。落地形态：endpoint 信任分级（每个 provider 配置 clearance level）+ 项目级敏感路径 / 模式标记 + 上下文装配时按 clearance 过滤或脱敏（独立 pipeline 阶段，带测试）+ 出域审计并入主持日志。**关键帧必须带 clearance 维度**（§4.3）：规则触发的关键帧（数字 / 金额 /"以 X 为准"）恰是最敏感内容，而关键帧驻留所有参会者上下文，等于向所有厂商广播。合规口径不做抽象定义，给策略文件 + 审计轨迹由组织自定。
3. **红队质量底线**："过弱的红队"应更尖锐——弱红队比没有红队更糟，它制造虚假制衡（同温层的伪装形态）。红队拆为一捆检查：开放式质证（需强推理）、引用核验 / 数字对账 / schema 校验（机械检查，弱模型或纯代码可胜任），按能力分级分工（§5 降级链）。底线用金丝雀评测标定：固定"埋雷"样本集（错误数字 / 错误 API 用法 / 隐性逻辑漏洞），候选模型抓出率低于阈值即取消红队资格（仍可做参与者），模型更新后重跑；测试集本身作为项目资产维护。§5 的"强制异构"相应改为"尽量异构 + 金丝雀门槛"——异构解决错误相关性，金丝雀解决质检能力，后者才是底线。
4. **回溯否决补偿覆盖面**：反转责任——可逆性是工具声明的属性而非会议系统推断：工具注册表每个动作带 `reversibility` 标注 + 补偿动作描述（saga 模式），黑 / 灰名单大部分成为派生数据，"逐场景细化"变成"给工具标注一次"，覆盖面由注册表完备性保证（该元数据当前不存在，需新建，建在工具层而非会议配置里）。灰区外部副作用优先**延迟执行**而非执行后补偿：不可逆尾巴挂起待追认、可逆部分先跑，把事后不可逆变成事前可逆，保住离场模式吞吐。补偿依赖数据基础：Tier 0 / 主持日志需扩展为行动日志（intent + 前置状态：git SHA、文件 hash）；代码类改动用 worktree-per-meeting 隔离，revert 几乎免费。
5. **记录员的 token 经济学**：不采用"独立调用 vs 搭便车"的二选一，改为**发言人 schema 前移 + 代码核验 + 事件驱动 LLM 补抽**策略。三层：（a）**声明层**——发言人 structured output 扩充 `claims` 数组（断言文本 + `fact|inference|opinion` + citation），摊入每轮发言的成本 +10–15%，这是唯一 per-round 开销；（b）**核验层**——citation 可解析（文件/行号/SHA 存在？引用片段含断言数值？）全部由代码完成，**零 token**，每轮同步执行；（c）**事件驱动 LLM 抽取**——仅在议题关闭、决策事件或每 K 回合触发增量抽取（仅新消息作为输入），挂入 §4.2 的 P4 后台异步队列，使用最便宜的已配置模型。3 席 × 20 回合会议估算：约 6 次 LLM 抽取 vs 逐轮 20 次，token 开销 ~70% 减少。规则触发的关键帧候选（数字/金额/"以 X 为准"模式）由正则抓取，零 token 全覆盖最敏感数据。实测决策门：若记录员 token/发言人 token > 0.3，或 assertion recall < 80%，调整 K 值或抽取模型。现有 `SubagentProgress.costUsd/inputTokens/outputTokens` 成本字段可直接扩展追踪。
6. **会议结论回流发起处的回路未闭合**：采用**回流包事件模式**——会议闭幕时向 `origin_ref` 所在会话发送 `meeting.conclusion` gateway 事件，注入的是一张结构化卡片而非聊天记录。数据流分两个方向：（a）**回流（会议 → 原对话）**：`MeetingReturnPacket`（decisions 逐字段 + contract 摘要 + open_items 计数 + stats），以 `display_kind` 系统消息渲染为可点击展开的富卡片，上下文装配时 decisions 逐字注入（≤1500 token 预算），全文经检索工具按需取；（b）**正向更新（原对话 → 会议）**：转换时快照背景材料，会议期间原对话新消息以 P4 背景更新推入会议，避免决议基于过期上下文。多源适配——kanban 卡片回流到卡片 comments + 状态更新；编排器自动升级回流为 subagent task result（父任务"挂起→等会议→resume with contract"，现有 `background-delegation.ts` 的子任务完成→新回合模式是直接先例）；对话转会议回流到原 thread。`SessionMessage.display_kind` 已有 `async_delegation_complete` 等系统消息类型，无需新 core type。会议中用户待回答事项（§4.2 P2）同时从回流卡片和通知中心可操作。
7. **§2 指标的度量方法学**：三层自动化评测体系。（a）**L0 机械层（代码，零 token）**：对产出物中每条定量断言核验 citation 可解析性（文件存在/行号有效/SHA 可定位）+ 引用内容含断言数值 → 产出 `ok|unresolved|invalid_citation|value_mismatch` 四分类分布。"溯源失败比例"指标本身就是机械可判定的，不是人工审计项。（b）**L1 语义层（跨厂商辅助模型）**：仅对 L0 通过的断言做 NLI entailment 判断（"引用段落是否支持此断言"），裁判模型必须不属于任何发言人模型家族，用一次性人工标注的固定 golden set（约 200 条）做金丝雀校准——每 session 混入 20% 已知样本测裁判 F1，修正度量值。**不是循环论证**：裁判做的是 narrow NLI entailment，与发言人 open-ended generation 的任务难度和失败模式完全不同。（c）**L2 人工抽样（月度，分层）**：全量高风险决策 + 分层 5% 全量产出，校准 L1 裁判并检测退化。各指标操作定义——一次通过率：行动日志中 `无 veto→redo 序列 / 总 task 数`；离场模式完成率：DelegationProfile 日志中白/灰名单无需用户介入比例；事后否决率：主持日志已签章后被否决 ÷ 全量签章；死锁：调度器 liveness probe（T 秒无 dequeue ∧ token 无 owner ∧ budget 不递减），必须为 0；成本/通过率比：复用现有 `SubagentProgress` 成本字段。以上全部机械可算，不依赖人工标注日常运行。
